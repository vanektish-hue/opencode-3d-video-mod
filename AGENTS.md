# AGENTS.md — инструкции для ИИ-агента

Этот репозиторий — **мод для OpenCode**: MCP-сервер, который даёт агенту два
инструмента в одном: **3D-моделирование** (процедурные модели, CPU-рендер, экспорт
glTF/OBJ, веб-вьюпорт на Three.js) и **видеомонтаж** (декларативный таймлайн →
один ffmpeg `filter_complex`: переходы, текст, оверлеи, цветокоррекция, аудио).

Прочитай перед работой: [`README.md`](README.md), [`docs/MOVIE.md`](docs/MOVIE.md)
(пайплайн фильма), [`docs/SCRIPT.md`](docs/SCRIPT.md) (текст озвучки фильма).
Эта инструкция приоритетна над общим «представлением о коде».

---

## 1. Как запустить / проверить

```sh
npm install          # deps: MCP SDK, ffmpeg-static, ffprobe-static, three, ws
node bin/setup.js    # доктор окружения (бинарники, шрифты)
npm test             # 17 тестов — обязательно зелёные перед сдачей работы
npm run demo         # шоурил -> exports/showreel.mp4 (~1-2 мин)
npm run movie:dry    # раскладка 10-минутного фильма без рендера
npm run movie        # полная сборка фильма (медленно: 15-30 мин)
```

Требуется **Node ≥ 20**. ffmpeg скачивается статически (`ffmpeg-static`), системный
ffmpeg не нужен. Для озвучки фильма дополнительно нужен Python + `edge-tts`
(`src/movie/tts.py`, см. п. 6).

## 2. Как подключён к агентской среде

`opencode.jsonc` в корне регистрирует MCP-сервер `creator`; OpenCode показывает его
инструменты как `tools.creator.*` в Code Mode. Основные:

- `modeling_*` — сцена, узлы, примитивы, материалы, свет, камера, превью
  (CPU-рендер в PNG), секвенция кадров, экспорт glb/obj;
- `video_*` — таймлайн, клипы, переходы, текст, оверлеи, аудио, рендер mp4,
  логотип;
- `showreel`, `movie_plan`, `movie_build` — демо и полный фильм;
- `ui_*` — веб-вьюпорт; `project_*` — состояние проекта.

## 3. Железные правила

1. **Не коммить и не клади в архив**: `node_modules/`, `tmp/`, большие видео
   (`exports/movie*.mp4`, `thumbnail.png`, `computer-mouse.png`, `project.json`).
   В `exports/` в репозитории лежит **только** `showreel.mp4` — не удаляй и не
   заменяй его. Остальное генерируется командами из п. 5.
2. **Код — чистые ES-модули** (`"type": "module"`), без новых внешних зависимостей
   без явной причины. Новый код — только в `src/` (или `scripts/` под QA).
3. **Windows-специфика**: рабочий путь может содержать кириллицу — **никогда не
   вызывай `ffmpeg`/`ffprobe` напрямую из шелла** (файл не найдётся). Пользуйся
   `runFFmpeg`/`runFFprobe` из `src/core/ffmpeg.js`. `node -e "...кавычки..."` в
   PowerShell ломается — пиши временный `.mjs` в `scripts/` или `tmp/`.
4. **Растеризатор (`src/core/raster.js`)**: никакого **back-face culling** —
   намеренно. Генераторы примитивов не согласованы: `makeBox` наматывает наружу,
   `paramSurface` внутрь, нормали тора — внутрь (в отличие от сферы/цилиндра).
   Любое «починить отсечение» дырявит корпус или показывает внутренности. Решение:
   все поверхности непрозрачны → рисуются обе стороны, z-буфер выбирает ближнюю.
   Не «чини» и не возвращай culling. Если примитив выглядит криво — чини
   геометрию/нормали примитива в `src/core/mesh.js`, а не растеризатор.
5. **ИИ не видит картинки**: для самопроверки рендера используй
   `scripts/ascii-preview.mjs <png> [cols]` (ASCII-силуэт) и числовые метрики
   (клиппинг яркости); для показа пользователю — `browser.preview`.
6. **Отдача результата**: файлы клади в `exports/`, показывай через
   `browser.preview`. Объясняй по-русски, коротко, по делу.

## 4. Структура

```
bin/            # CLI: mcp (stdio-сервер), ui, demo, setup, movie
src/core/       # mesh, scene, raster, mat, png, glb, mouse, frames, video, ffmpeg, project
src/mcp/        # MCP-сервер: схемы инструментов + обработчики
src/ui/         # HTTP+WS вьюпорт
src/demo/       # шоурил (3D + логотип + монтаж + аудио)
src/movie/      # фильм: script (сценарий), voice (озвучка), tts.py, audio, music, wav,
                #   models (10 моделей), clips (рендер облётов), build (раскладка+сборка)
web/            # статика вьюпорта (index.html, viewport.js, timeline.js, app.js, styles.css)
scripts/        # QA/утилиты (ascii-preview, movie-voice, movie-thumbnail, verify-movie, ...)
tests/          # node:test — 17 тестов (mouse, video, mcp, movie, raster)
docs/           # MOVIE.md (пайплайн фильма), SCRIPT.md (текст озвучки)
```

## 5. Типовые операции

**Правка модели → проверка:** меняешь `src/movie/models.js` / `src/core/mesh.js` →
прогон `npm test` + рендер кадра (`scripts/movie-thumbnail.mjs` рендерит мышь,
или `browser.preview` — если рендер из интерфейса). Проверь, что силуэт целый,
нет просвечивания.

**Сборка фильма заново:** `npm run movie:voice` (озвучка, кэшируется по сценам)
→ `node bin/movie.js exports/_dry.mp4 --dry` (раскладка) →
`node bin/movie.js exports/movie-new.mp4 --hq --reuse` (полная сборка) →
`node scripts/verify-movie.mjs exports/movie-new.mp4` → `node scripts/movie-thumbnail.mjs`
→ заменить `exports/movie.mp4` (на Windows сначала `Move-Item -Force` — файл может
держать блокировку из просмотрщика). **Не пересобирай фильм без необходимости**:
полный HQ-рендер ≈ 15-30 мин.

**Тайминги фильма:** каждая сцена = озвучка + пауза (`GAP`), сцены автоматически
продлеваются на время своих переходов (`xfade`), поэтому реплики не должны
накладываться. Константы — в `src/movie/build.js` (`LEAD`, `GAP`, `TARGET`).
Не меняй вручную отдельные тайминги — правь сценарий в `src/movie/script.js`
и пересинтезируй только изменённые сцены (кэш по хэшу сцены).

## 6. Озвучка (только для фильма)

`src/movie/voice.js` вызывает `tts.py` (edge-tts). Нужен Python:
```sh
pip install edge-tts
```
Озвучка кэшируется в `tmp/movie/narration.json`; при правке текста одной сцены
пересинтезируется только она. Консоль может «портить» кириллицу — файлы при этом
корректны (UTF-8).

## 7. Ограничения (не пытайся «починить» в общем виде)

- CPU-растеризатор медленный: 1280×720 кадр — сотни миллисекунд. Для превью —
  меньше размер / `aa:1`.
- Шрифты по умолчанию из `C:\Windows\Fonts`; на других ОС задай `FONT_DIR`.
- Микс аудио проходит `loudnorm` (−16 LUFS), это норма.
